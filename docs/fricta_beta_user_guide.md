# Fricta Beta User Guide

Welcome to the Fricta Beta! This guide covers everything you need to know to get started.

## What is Fricta?
Fricta is an autonomous UX and UI auditing platform. It analyzes digital experiences using specialized AI agents to identify friction points, visual inconsistencies, and cognitive overloads that frustrate your users.

## Who is it for?
Fricta is designed for Product Managers, UX Designers, and Frontend Engineers who want automated, actionable insights into their user flows without spending weeks on manual usability testing.

---

## How to Run Your First Audit

1. **Create a Project**: A project represents the application or website you are auditing. Click "New Project" and give it a name.
2. **Define Your Persona**: Tell Fricta who your target user is (e.g., "A first-time user trying to check out").
3. **Start the Audit**: Provide the URL or the user flow you want analyzed. Fricta's agents will navigate the flow, looking for issues.
4. **Wait for Completion**: Audits can take a few minutes as the agents deeply analyze the steps. Grab a coffee!

---

## How to Read Your Findings

When the audit finishes, you will receive a **Report**.
- **UX Findings**: Logical issues, confusing copy, or broken user journeys.
- **Visual Findings**: Alignment issues, contrast problems, or layout breaks.
- **Cognitive Signals**: Moments where the user would likely feel confused or frustrated.

Each finding comes with a **Severity** rating (Critical, High, Medium, Low) and an actionable **Recommendation**.

---

## Known Limitations (Beta)
- Audits may take up to 5 minutes to complete depending on complexity.
- Highly interactive Canvas/WebGL elements cannot be fully audited yet.
- Mobile viewport simulations are currently locked to specific standard resolutions.

*(Please check the `Known Issues` board for more specific technical limitations).*

---

## Support Process
If you run into an issue or have an idea to make Fricta better:
1. Click the **Submit Feedback** button in the app, or
2. Open an issue directly on our GitHub repository using the provided Beta Feedback templates.
3. If you encounter a blocking bug, please include your **Workflow ID** (found at the bottom of your report) so we can investigate.
